# Скилл: долговременная память проекта AniVibe

Применять в КАЖДОЙ сессии работы над этим репозиторием.

## Перед стартом любой задачи
1. Прочитай `ARCHITECTURE.md` (карта файлов, БД, тема, стейт, плеер, тир-листы).
2. Прочитай `PROJECT_HISTORY.md` (последние 8 изменений).
3. Только потом открывай код — и точечно.

## Экономия токенов
- Файлы >250 строк не читать целиком: `grep` по имени символа → `read` с `offset/limit` вокруг попадания.
- Никогда не открывать файлы из `.cursorignore`: медиа, `*.patch`, фикстуры, локи, сборочные артефакты.
- Не дергать `ls -R`/полные дампы папок — целевые `fd`/glob-запросы.

## Декомпозиция (правило 300 строк)
- Файл длиннее ~300–350 строк после правки — выносить новую логику в отдельный файл рядом по фиче: отдельный View, sheet, helper или `*Store`/`*Controller`.
- Именование по существующей схеме: `Anivibe/Features/<Фича>/<Имя>.swift`, ядро — `Packages/AnivibeCore/Sources/AnivibeCore/<Раздел>/`.

## После задачи
- Запись в ВЕРХ `PROJECT_HISTORY.md` под заголовком: дата и название задачи; изменённые/созданные файлы (1 строка сути); изменения БД/API/стейта; нюансы и edge-cases.
- Хранить только 8 последних записей; более старые — в `HISTORY_ARCHIVE.md`.
- Если менялась схема БД или структура папок — синхронно править `ARCHITECTURE.md`.
