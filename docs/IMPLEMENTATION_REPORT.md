# Итоговый отчёт о доработке Anivibe — 13.10.2026

## Результат и границы

Подготовлена обновлённая версия существующего SwiftUI-проекта, не переписанного с нуля. Исправлены основные пути эпизодов/плеера/прогресса, улучшены каталог/библиотека/локальное оформление, расширен существующий Supabase Auth и устранены несколько проблем целостности/изоляции данных.

**Полное ТЗ из 24 разделов не завершено.** Реализованы основные изменения первых этапов и часть auth. Этапы друзей/совместного просмотра/валюты/магазина/росписей/комментариев/модерации/уведомлений остаются. Они не заменены локальными демонстрациями и не представлены пустыми кнопками.

## Исправления

1. Steel Ball Run: найден реальный конфликт структуры AniList и Kodik. Доступные элементы источника больше не скрываются лимитом каталога; они показываются в отдельном выборе с сохранением оригинального сезона/номера/ID. Не захардкожены четвёртая серия, duration или offset.
2. Контролы: управляемая панель, пауза таймера во время выбора, seek/buffering/preparing, новый таймер после взаимодействия.
3. Качество: сохранение позиции и паузы, блок записи во время восстановления, проверка актуальности AVPlayerItem после await, ошибку восстановления видно пользователю.
4. «Смотрю»: запись только после фактического playback, история не создаётся при открытии карточки или тестового потока; UI обновляется через существующий Store.
5. Старые/гостевые аккаунты: отдельные файлы, отсечение запоздалых sync/player событий другого аккаунта.
6. История: удалённые записи передаются tombstones и не возвращаются от устаревшей строки сервера.
7. Sync: страницы вместо прежнего ограничения 1000, отдельный source_key, серверный last-write-wins и сохранение watermark только при успешной записи.
8. Повреждённые JSON не затираются пустым состоянием. Ошибки сохранения папок отображаются.
9. Общий встроенный Kodik token удалён. CI URL экранируются для xcconfig. Сборка CI зависит от тестов.
10. Отмена/обновление Auth: поздний refresh не восстанавливает вышедшую сессию.

## Добавленные и доработанные возможности

- Русские названия и описания Shikimori, сохранение оригинала, fallback без блокировки открытия деталей.
- Поиск по aliases и проверенным MAL ID; ограниченный кэшированный индекс, typo ranking, транслитерация запроса, дедупликация.
- Русские жанры интерфейса без подмены ID фильтров.
- Множественный выбор папок из каталога и описания.
- Серии не показываются списком под описанием; каталог и источник доступны через отдельную панель.
- Resume/история основного плеера знают точную нумерацию материала/озвучки. Альтернативный плеер сохранён, но его прогресс не интегрирован.
- Native drag/drop с сохранением порядка папок/тайтлов **локально**.
- Сдержанные карточки, presets/custom accent, сброс, контраст заполненных кнопок.
- PhotosPicker, downsampling до 2048 px, JPEG ≤4 МБ, предпросмотр/положение/подложка/удаление фона.
- Закрепление библиотеки внутри приложения, не системный виджет.
- Email signup verify/resend через GoTrue; OTP template/config; native Google browser + PKCE/state/code exchange.

## База данных и backend

Архитектура Supabase сохранена: GoTrue/Auth, PostgREST, PostgreSQL/RLS. Добавлены 2 миграции:

- source_key в progress/history; новый PK `(user_id, anime_id, episode, source_key)`;
- tombstones истории, updated_at, индекс и серверная проверка устаревших обновлений.

Старые строки progress сохраняются с пустым scope, проверено на PostgreSQL. Новая версия клиента требует синхронного обновления серверной схемы и всех устройств: старый on_conflict после миграции не работает. Библиотеки аккаунтов локально изолированы; гостевой файл сохранён и не автоматически импортируется в аккаунт.

Новых таблиц друзей, профилей, балансов, магазина, сессий, комментариев и модерации нет. Такой сервер не заявлен как готовый.

## Что нужно заполнить самостоятельно

- Bundle ID/Apple Development Team/подпись и доступ к Mac/Xcode.
- Supabase project/API URL и publishable/anon key; применённые миграции.
- Собственный разрешённый Kodik partner token или manifest легальных потоков.
- SMTP провайдер/домен/SPF/DKIM/DMARC/SMTP credentials и sender.
- Google consent/client ID/client secret и оба вида callback.
- Для self-host: домены, TLS, выбранный Supabase release, DB/JWT/server keys, firewall, backups, мониторинг.

Секреты не находятся в отчёте или исходниках. Не включайте server secrets в IPA. Наличие источника не означает наличия прав на контент.

## Оставшиеся ограничения и риски

1. iOS-слой не собран: возможны ошибки типов/платформенных API и поведения, невидимые parser-у. Нельзя называть приложение готовым к выпуску.
2. Source↔catalogue mapping не выдуман. Автоматического verified mapping для объединённых/разделённых выпусков нет; вместо этого используются отдельные корректные списки и ID.
3. Непросмотренные источники, DRM, права на конкретные видео и условия прямого HLS не проверены. Не подключайте неразрешённые источники.
4. У альтернативного KodikPlayerScreen/WebView нет общего прогресса/истории.
5. Папки, их порядок, акцент, фон и PIN библиотеки сохраняются лишь на устройстве; облачной синхронизации настроек/папок нет.
6. Typo/alias поиск работает по доступным источникам и недавно кэшированному индексу; это не полноценный глобальный fuzzy search сервер и не база выдуманных переводов.
7. Описания без перевода остаются оригинальными; отдельный сервис машинного перевода не реализован.
8. Guest → account импорт требует подтверждаемого сценария, ещё не добавлен. Гостевые файлы не удаляются.
9. OTP per-challenge hard limit/полный сценарий recovery и редактирования профиля/ручное linking-unlinking не завершены. Нужны проверенные серверные политики и end-to-end тесты.
10. Sync использует клиентские timestamps и offset pagination, не транзакционный snapshot. Длительный offline, сильное расхождение часов, concurrent inserts и пересечение нескольких устройств требуют отдельной проверки/перехода к серверным revisions/cursor. Память для больших библиотек и tombstone cleanup ещё не оптимизированы.
11. Экономика/социальные награды отсутствуют; существующий клиентский progress нельзя использовать как доказательство просмотра или основание денежного начисления.
12. Нет нагрузочных замеров RAM/VPS, мультиязычной архитектуры переключения UI и полного accessibility-аудита.
