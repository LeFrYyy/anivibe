# Anivibe — багфикс-обновление 15.10.2026

Обновление исходников поверх `Anivibe-social-fixed-v2.zip`. Основной фокус — навигация, сохранение просмотра и временное скрытие незавершённых функций. Готовой IPA в этом архиве нет.

## Что изменено

### Переходы из профиля

- Профиль открывает списки через типизированный маршрут `LibrarySection` в одном `NavigationStack`.
- Встроенная библиотека больше не регистрирует повторные назначения для `Anime` / `AnimeSnapshot`: ими управляет стек профиля. Самостоятельная вкладка библиотеки по-прежнему владеет своим стеком.
- Вход в «Просмотрено», остальные списки, историю и избранное использует одну схему навигации. При смене аккаунта путь сбрасывается.

### История, серия и позиция просмотра

- Просмотренная серия Kodik больше не делает весь тайтл невидимым в «Продолжить просмотр». Сохраняется точный ключ последней серии источника; следующая выбирается только из фактического списка Kodik, включая разрывы нумерации и сезоны.
- Если следующей серии в выбранной озвучке пока нет, приложение предлагает выбрать серию/озвучку, а не молча запускает первую.
- Перед закрытием нативного плеера приложение дожидается локального сохранения и обновления видимой библиотеки. Это важно при немедленном повторном открытии тайтла.
- Сохранение передаёт время самого события. Поздний запрос старого плеера не перезаписывает новую позицию и не возвращает `lastEpisode` к предыдущей серии.
- JSON-хранилище теперь пишет даты с долями секунды. Старые даты без дробной части читаются. Для старых одинаковых дат используется последняя открытая серия и порядок записи.
- Восстанавливается озвучка точного сохранённого источника, если пользователь не выбрал другую явно. Прогресс разных озвучек/видео не смешивается. Путь через реестр провайдеров использует те же ключи прогресса, что и страница тайтла.
- При паузе, перемотке и выходе берётся актуальная позиция AVPlayer, в том числе 0 секунд. Временно неизвестная длительность не стирает ранее известную.
- Проценты в истории и строках библиотеки учитывают прогресс источника. Запоздавшее сохранение не восстанавливает только что удалённую историю; новый просмотр может снова добавить её.
- Защита от записей в чужой аккаунт сохранена; плеер закрывается при смене аккаунта.

### Временно скрытые функции

- Скрыты вход в «Вместе в Anivibe», кнопки «Смотреть вместе», связанные переходы из профилей друзей, магазин и инвентарь сообщества.
- Обычные друзья, поиск, заявки и публичные профили остаются доступны.
- Фоновый опрос и realtime сообщества выключены, пока обе функции скрыты.
- Реализация, монеты, предметы, комнаты и серверные данные не удаляются. Флаги находятся в `Anivibe/App/AppFeatures.swift`: `sharedWatchingEnabled = false`, `friendshipShopEnabled = false`. Это скрытие текущего клиента, а не запрет серверных RPC для ранее выпущенных версий.

### «Брошено»

- Отдельный статус `dropped`, не переименование «Отложено».
- Вкладка, счётчик профиля, меню статусов и контекстные действия.
- Локальное сохранение, облачная синхронизация и счётчик в разрешённой к просмотру библиотеке друга.
- Тайтлы со статусом «Брошено» не предлагаются в «Продолжить просмотр», но история, прогресс и избранное сохраняются. Для возобновления списка нужно выбрать «Смотрю».

### Дополнительное исправление

Свайп «Убрать из избранного» теперь только снимает флаг избранного, а «Убрать из списка» — только статус. Раньше одинаковое действие помечало тайтл удалённым из всей библиотеки, что также убирало его из продолжения просмотра. Полное удаление оставлено отдельным явным пунктом контекстного меню. История и прогресс не очищаются этими свайпами.

## Как применить

1. Сохранить резервную копию текущего проекта и базы. Использовать исходники из этого архива целиком: изменения затрагивают приложение и локальный пакет `AnivibeCore`.
2. **До распространения новой версии применить миграцию Supabase** `supabase/migrations/20261015000000_bugfix_library_status.sql` после существующих миграций. При настроенном Supabase CLI — обычный `supabase db push`; либо выполнить именно новый SQL через SQL Editor своей базы. Старые миграции повторно вручную не запускать.
3. Миграция расширяет допустимые статусы и добавляет `dropped` в существующий RPC статистики. Старые строки, политики доступа, приватность и пагинация не удаляются и не открываются публично. Без миграции сервер будет отклонять синхронизацию нового статуса.
4. Открыть `Anivibe.xcodeproj` в Xcode или запустить существующий workflow `iOS` в GitHub Actions. Новые Swift-файлы автоматически входят в синхронизированную группу проекта и пакет.
5. Прогнать проверки ниже и проверить сценарии на симуляторе/устройстве. Не удалять установленное приложение ради обновления: так можно потерять локальную несинхронизированную библиотеку.

## Проверки и честные ограничения

В этой среде выполнены:

- `python3 -m unittest discover -s scripts -p 'test_*.py' -v` — **69 проверок, успешно**; из них 14 новых проверок связности этого обновления. Это проверки исходников и Python-логики, не выполнение SwiftUI.
- `python3 scripts/check_project.py` — успешно.
- Проверка синтаксиса Python, YAML workflow и plist — успешно.
- Сравнение с входным архивом: старые миграции не менялись; тело RPC профиля изменено только добавлением счётчика `dropped` и `create or replace`.

Добавлены, но **не выполнялись здесь**:

- 20 поведенческих XCTest в `Packages/AnivibeCore/Tests/AnivibeCoreTests/Bugfix20261015Tests.swift`.
- Обновлена существующая проверка точного якоря завершённой серии источника, без угадывания следующего номера.
- 2 проверки PostgreSQL: новый статус/счётчик без нарушения приватности и совместимость прежних статусов.

**Swift, Xcode, симулятора iOS и PostgreSQL в этой среде нет. Сборка, XCTest, SQL-миграция на реальной БД и воспроизведение на устройстве не проверены.** Новая проверка исходников включена в существующий workflow; XCTest и тесты БД будут запускаться его штатными заданиями. Успешного прогона CI для этого архива пока нет.

Резервный встроенный **веб-плеер Kodik** остаётся отдельным режимом: сериями и прогрессом в нём управляет сам Kodik. Автоматический импорт его позиции в Anivibe в это обновление не добавлен; приложение показывает предупреждение. Исправления сохранения относятся к основному нативному плееру Anivibe. Неоднозначные старые ключи источников не пересчитываются по названиям/номерам, чтобы не переносить позицию в другое видео.

## Что проверить вручную перед выпуском

- [ ] Профиль → «Просмотрено» → любой тайтл: открывается страница аниме; «Назад» возвращает в тот же список, затем в профиль. Повторить для остальных списков, истории и избранного.
- [ ] Перейти между вкладками списков, включая «Брошено», вернуться в профиль и открыть другой список: выбран правильный раздел.
- [ ] Просмотреть часть серии, закрыть и сразу нажать «Продолжить»: совпадают источник, серия и позиция. Повторить после обычного перезапуска и после ухода в фон.
- [ ] Досмотреть серию Kodik до ≥90%, закрыть: карточка остаётся; продолжение выбирает следующий реальный элемент списка, а не первую серию. Проверить последнюю доступную серию и список с разрывами нумерации.
- [ ] Просмотреть другой тайтл с другой озвучкой, вернуться к первому: его источник восстанавливается; ручной выбор иной озвучки не отменяется автоматически.
- [ ] Перемотать к 0, закрыть после завершения перемотки, открыть снова: не возвращается прежний положительный таймкод.
- [ ] Убрать тайтл из избранного свайпом: он остаётся в «Смотрю» и в продолжении. Убрать из списка: избранное и история остаются.
- [ ] Добавить в «Брошено», перезапустить, синхронизировать на втором устройстве: статус и счётчик сохраняются; приватная библиотека не видна другим.
- [ ] Удалить историю сразу после просмотра: старое событие паузы не возвращает её; новый просмотр создаёт новую запись.
- [ ] Проверить профиль, страницу аниме и профиль друга: входов в совместный просмотр и магазин нет; обычные заявки/поиск друзей работают.
