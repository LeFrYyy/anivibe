# Anivibe v4.1 — исправление сборки сетки папки

Точечная правка поверх `Anivibe-flat-design-v4.zip`. Архив содержит полный проект с предыдущими багфиксами и плоским дизайном; это **исходники, не IPA**.

## Ошибка

В `Anivibe/Features/Home/FolderViews.swift` новая сетка использовала:

```swift
ForEach(collection.items) { anime in
```

Но `AnimeCollection.items` — массив `[AnimeSnapshot]`. У `AnimeSnapshot` есть поле `id: Int`, однако тип не объявлен как `Identifiable` и не получает такое соответствие автоматически только из-за наличия поля `id`. Вызов `ForEach` без параметра `id` требует этого соответствия.

Исправлено на явный стабильный идентификатор тайтла:

```swift
ForEach(collection.items, id: \.id) { anime in
```

Это единственное изменение Swift-кода относительно v4. Используется идентификатор аниме, а не номер ячейки: при перестановке тайтлов идентичность элементов сохраняется. Менять `AnimeSnapshot`, сериализацию, сохранённые папки или серверную схему не требуется.

В присланном фрагменте лога виден сбой компиляции `FolderViews.swift`, но нет исходной строки диагностики `error:`. Описанный выше дефект найден непосредственно в исходниках v4; успешную сборку после его исправления ещё должен подтвердить Xcode/CI.

## Как применить

Для текущего репозитория на v4 достаточно заменить один файл:

`Anivibe/Features/Home/FolderViews.swift`

Либо вручную добавить `, id: \.id` в указанный `ForEach`. В полном архиве этот файл расположен внутри внешней папки проекта `Anivibe/`.

Также обновлён `scripts/test_flat_design.py`: добавлена проверка явного идентификатора. Она уже вызывается существующим шагом CI; workflow менять не нужно.

После переноса правки выполните commit/push и запустите новую сборку GitHub Actions. Повторный запуск старого workflow без нового коммита использует прежний код.

**Новых миграций, ключей и настроек нет.** Статус «Брошено», исправления прогресса и навигации, скрытые совместный просмотр/магазин и дизайн v4 сохранены.

## Проверка

- До изменения Swift-файла новая source-проверка падала на ошибочном `ForEach`.
- После правки прошли **83 Python-проверки исходников/конфигурации**, включая эту регрессионную проверку.
- Прошла статическая проверка проекта `scripts/check_project.py`.
- В сравнении с v4 изменена ровно одна строка одного Swift-файла; core-модели, серверные файлы и остальные Swift-файлы не менялись.
- Логи: `FOLDER_BUILD_FIX_CHECKS.txt`. Список изменений относительно v4: `FOLDER_BUILD_FIX_FILE_CHANGES.json`.

**Это не нативная компиляция.** Здесь нет Swift/Xcode и симулятора iOS; сборка приложения и XCTest не запускались. Поэтому исходная ошибка в коде исправлена, но успешный результат iOS-сборки здесь не заявляется.

Если новая сборка тоже завершится ошибкой, нужен полный `simulator-build.log` из артефакта **`ios-build-logs`** либо первая строка `error:` с несколькими соседними строками. Сам по себе `exit code 65` — итоговый код `xcodebuild`, а не описание причины.
