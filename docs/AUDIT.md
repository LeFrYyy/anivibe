# Технический аудит Anivibe — 13.10.2026

## Исходная архитектура

- Нативный iOS 17+, Swift 5, SwiftUI, Observation, NavigationStack/TabView.
- MVVM по экранам; AppEnvironment является корнем композиции.
- Независимый Swift Package AnivibeCore: модели, каталог, HTTP, видео, библиотека, Auth и Sync.
- AniList GraphQL — основной каталог; в каждой записи отдельная часть/сезон.
- Kodik и AniLiberty/Anilibria — адаптеры видео; собственный разрешённый HLS-манифест и тестовые Apple/Blender-потоки сохранены.
- Основной плеер — AVPlayer с собственной панелью; альтернативный KodikPlayerScreen и веб-fallback сохранены.
- `Application Support/Anivibe/library.json` и `collections.json`; настройки UserDefaults; токены Keychain.
- Supabase GoTrue/Auth + PostgREST + PostgreSQL. В исходной схеме лишь библиотека, прогресс и история; друзей/валюты/профилей/комментариев не было.
- История и режим локальной библиотеки уже существовали, они доработаны, а не заменены новой демонстрацией.

## Найденные причины проблем

### Steel Ball Run

Проверены реальные ответы AniList и Kodik. В AniList запись 210482/MAL 61469 обозначает 2nd & 3rd STAGE, `episodes=11`, `nextAiringEpisode.episode=4`, streamingEpisodes пуст. Каталожный builder корректно вычислял 3 вышедших эпизода.

В Kodik для того же MAL ID найдено 29 материалов/переводов; у части из них сезон 6 имеет ключи 1,2,3,4. Некоторые студии предоставляют только 1–3 или меньше. Материал `serial-73739`, перевод 609/AniDUB содержит 4 элемента. Эти факты сохранены в fixtures; там нет токена и подписанных ссылок на потоки.

Потеря элемента происходила **при построении экрана по данным каталога**, а не из-за отсутствия четвёртого элемента в ответе Kodik. Дополнительно сезон источника автоматически flatten-ился, а разные материалы одной студии могли отбрасываться или объединяться по номеру/названию.

Решение: показывать источник отдельно, сохранять его материал/перевод/сезон/номер и не угадывать соответствие каталоговой части. Канонические эпизоды не воспроизводятся через неявное Kodik season-flattening. Число 4 нигде не захардкожено в бизнес-логике.

### Скрытие контролов

Таймер учитывал только воспроизведение и scrubbing; вложенные SwiftUI Menu не давали достоверного состояния открытия/закрытия. Таймер мог скрыть родительские контролы во время выбора. При замене AVPlayerItem периодический observer мог сохранить время до завершения восстановления, а новый item автоматически запускался даже после паузы.

Решение: отдельная управляемая панель настроек, единая deadline-политика, блокирующие состояния, восстановление позиции до записи прогресса, сохранение паузы, защита от устаревших обработчиков.

### Библиотека и синхронизация

- Один файл библиотеки для всех аккаунтов: риск загрузить чужую локальную библиотеку следующему вошедшему пользователю.
- История удалялась только локально: merge мог вернуть старые строки.
- GET имел лимит 1000 без пагинации.
- Сервер upsert не отклонял устаревшее обновление: правило last-write-wins существовало лишь в клиентском merge.
- Старые коды Linux SDK не поддерживали URLSession.data(for:) и NSLock.withLock в используемой сборке Swift.
- Повреждённый локальный JSON мог быть заменён новым пустым состоянием.
- Общий рабочий Kodik token хранился в исходниках и xcconfig.
- URL из GitHub secrets записывались в xcconfig без защиты от комментария `//`.

Все перечисленные пути затронуты исправлениями и регрессионными проверками. Это не равнозначно полному независимому аудиту безопасности.

## Краткий план и фактическая последовательность

1. Сохранить архитектуру, загрузить реальную метаинформацию эпизодов, отделить источник от каталога.
2. Исправить контролы, качество и запись начала просмотра; выполнить тесты ядра.
3. Доработать каталог/папки/историю, русский источник, ранжирование, сохранение оригинала; проверить реальные API.
4. Устранить опасное смешивание аккаунтов, soft-delete и серверные конфликты; проверить миграции и RLS на PostgreSQL.
5. Добавить локальное оформление и native drag/drop; проверить чистую логику порядка, синтаксис iOS.
6. Подключить существующий GoTrue к OTP и native Google PKCE без самодельного auth-сервера; тестировать REST-контракты.
7. Остановиться до социальных этапов, для которых нужна отдельная согласованная схема, серверные транзакции, UI и реальные end-to-end проверки.

Пункт 4 намеренно выполнен раньше социальной разработки: переносить следующие функции поверх смешанных аккаунтов и исчезающей истории было бы небезопасно.

## Совместимость

Гостевой `library.json` сохранён. Аккаунты используют `library-user-<safe-encoded-user-id>.json` рядом с ним. Гостевая библиотека не импортируется в аккаунт автоматически; облачные данные после входа загружаются в отдельный файл. Старые несинхронизированные гостевые записи остаются доступны после выхода. Для явного переноса в аккаунт нужен отдельный подтверждаемый импорт — он пока не добавлен.

Новые Swift Codable-поля опциональны, старые данные читаются. Миграция сохраняет каталоговый прогресс с `source_key=''`, затем расширяет ключ уникальности. Разные материалы/озвучки не используют одну позицию воспроизведения.
