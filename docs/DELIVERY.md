# Anivibe — доработка на основе Anivibe (21).zip

## Основа и границы

Исходная основа — повторно присланный старый архив Anivibe (21).zip. Сохранены его навигация, главная, дизайн папок, KodikVoicePicker и веб/нативный альтернативный плеер. Перенесены целевые исправления ядра, основного плеера, русскоязычного каталога и авторизации; не выполнена замена всего приложения предыдущей переработанной версией.

ТЗ из 24 разделов НЕ завершено целиком. Это один полный архив с реально написанной частью функций, а не обещание готового магазина/совместного просмотра. Нереализованные социальные функции не представлены пустыми кнопками.

## Причина пропавших озвучек

В предыдущей доработке Kodik отключался без отдельно указанного токена. В этой версии конфигурация Kodik из предоставленного старого архива сохранена. Отдельный встроенный fallback-token в Swift не добавлен; источник создаётся из xcconfig. Проверен реальный запрос метаданных с исходной конфигурацией: HTTP 200, без API error, 29 материалов/переводов для тайтла регрессионного теста. Это НЕ проверка воспроизведения, лицензии или качества всех озвучек.

Упакованный в приложение клиентский токен извлекается из IPA. Перед публичным выпуском используйте собственный разрешённый партнёрский доступ и соблюдайте правила провайдера. Service-role, SMTP-пароли и Google Client Secret в архив не добавлены. URL и публичный Supabase publishable key пользователя — в Config/Supabase.xcconfig.

## Изменения

- Сохранён старый выбор озвучки над кнопкой просмотра.
- Серии вынесены из описания в отдельное окно; старый интерфейс озвучек/серий источника открывается отдельно.
- Фактические эпизоды источника доступны без ограничения количеством эпизодов каталога; сохранены сезон, номер, материал и scope прогресса. Оригинальная нумерация не выдаётся за подтверждённое сопоставление каталога.
- Основной AVPlayer удерживает контролы во время настроек, перемотки и буферизации; качество переключается с сохранением позиции.
- Библиотека аккаунтов изолирована, поздние события плеера/синхронизации не записываются в другой аккаунт. Гостевые данные не импортируются автоматически.
- Удаление истории синхронизируется через tombstones; добавлена пагинация.
- Русскоязычные данные Shikimori, aliases/typo/transliteration ranking и fallback оригинальных данных.
- Множественное добавление в папки из каталога и описания.
- Локальное перетаскивание папок/тайтлов с сохранением прежнего дизайна; подтверждение удаления папки.
- Локальный фон из PhotosPicker с уменьшением изображения, предпросмотром, положением и затемнением.
- Цветовая тема с presets/custom/reset и контрастом кнопок.
- Signup OTP verify/resend; Google PKCE в системном браузере; publishable key отправляется в apikey, пользовательский JWT — в Bearer.
- Настоящие серверные профили: UUID, уникальный username, имя, bio, даты и приватность.
- Настоящие друзья: поиск username, просмотр доступного профиля, запрос, принятие/отклонение, отмена и удаление.
- Приватный профиль виден владельцу, принятым друзьям и адресатам собственных запросов. Публичный виден авторизованным пользователям. Email не хранится в публичной таблице.
- Friend RPC определяет инициатора по auth.uid(), запрещает прямое изменение edges, сериализует пары и проверяет лимит обоих участников (10 друзей).
- Отправка запросов: интервал 10 секунд, максимум 50 в сутки, 20 исходящих pending и 50 входящих pending. Это не полноценная anti-Sybil/anti-spam система.

## Supabase: что нужно выполнить

Если первые три миграции уже были выполнены в вашем проекте, выполните ТОЛЬКО новую, один раз:

`supabase/migrations/20261013020000_profiles_friends.sql`

В Dashboard → SQL Editor создайте запрос, вставьте весь файл и выполните Run. Миграция создаёт профили существующих пользователей и триггер для новых; библиотеку, историю и прогресс не удаляет. Не выполняйте повторно первые три миграции, не отключайте RLS и не запускайте db reset.

Для полностью нового проекта выполняются четыре файла в порядке имён:

1. 20261011000000_anivibe_init.sql
2. 20261013000000_source_episode_identity.sql
3. 20261013010000_history_tombstones_lww.sql
4. 20261013020000_profiles_friends.sql

Из SQL-папки tests НИЧЕГО не выполняйте в облачном Supabase: там имитация Auth для локальных проверок. При работе через Supabase CLI сначала сверяется migration ledger, особенно если предыдущие SQL применялись вручную.

Google-провайдер и Redirect URL, настроенные пользователем ранее, остаются. SMTP/email provider, Confirm email, шестизначный OTP, шаблон `{{ .Token }}` и лимиты отправки настраиваются в Dashboard. Локальный config.toml не изменяет облачный проект автоматически. Без SMTP Google может работать; email-регистрация обычных пользователей требует настройки доставки.

## Проверка вручную

1. Обновить репозиторий, выполнить новую SQL-миграцию и запустить Actions через push main.
2. Убедиться, что прошли jobs тестов ядра/БД, Debug simulator build и Release device build.
3. Установить подписанный IPA. Проверить старый выбор озвучки до просмотра и в доступных настройках видео.
4. Проверить серии источника, смену качества/скорости, сохранение позиции и отсутствие ложной истории от открытия карточки.
5. Войти через Google; открыть профиль и выбрать username, имя, bio. Изменить видимость на публичную.
6. Вторым аккаунтом найти username, отправить запрос; первым принять. Обновить списки, затем удалить/отменить/отклонить в соответствующих состояниях.
7. Проверить приватный профиль посторонним аккаунтом и убедиться, что почта, история и библиотека не раскрываются.
8. На двух устройствах проверить прогресс/историю, выход и смену аккаунта.
