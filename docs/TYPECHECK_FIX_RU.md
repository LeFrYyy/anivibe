# Исправление type-check timeout в CosmeticMediaView

В новом присланном логе единственная диагностика Swift — `CosmeticMediaView.swift:93:9: the compiler is unable to type-check this expression in reasonable time`. Она указывает на вычисление `CosmeticProfileIdentity.identity`, а не на SQL и не на обработчики `catch`.

Убрана одна длинная цепочка перегруженных `+`, optional chaining, тернарного оператора, `filter/map/sorted/joined`. Вместо неё используются отдельно типизированные строки, простой цикл по надетым предметам, сортировка массива ID и `joined` для четырёх частей ключа. Состав ключа прежний: текущий аккаунт, целевой профиль, версия профиля и отсортированные ID собственной косметики. Проверки приватности, сброс кэша при смене аккаунта, медиа и внешний вид не менялись.

## Минимальное обновление

1. Заменить только `Anivibe/Features/Community/CosmeticMediaView.swift` в своём репозитории на новый файл. Предыдущую правку `WatchRoomViews.swift` оставить: она сохранена и в полном архиве.
2. Либо выполнить `git apply --check typecheck-fix.patch`, затем `git apply typecheck-fix.patch` поверх предыдущей социальной версии. Этот patch меняет только один Swift-файл.
3. Сделать commit/push и проверить **новый** запуск GitHub Actions. Перезапуск старого упавшего job без нового коммита может снова собирать прежние исходники.

Новых миграций нет; существующие SQL сохранены побайтово. Повторно запускать уже применённые миграции из-за этой правки не нужно.

В полном архиве также обновлён source-regression guard в `scripts/test_swift_error_shadowing.py`; существующий CI уже вызывает этот скрипт. Здесь прошли 55/55 source/config/tool проверок и `check_project.py`. Это не результат компиляции Swift: `swift` и Xcode в среде подготовки отсутствуют. Успешную нативную сборку пока должен подтвердить CI.

`community-update.patch` заново собран для исходной базы `Anivibe-improved.zip` и включает оба исправления. `build-fix.patch` — только предыдущая правка 7 обработчиков; `typecheck-fix.patch` — только новая правка ключа. Не применять patch повторно поверх уже исправленных файлов.
