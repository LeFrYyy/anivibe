# Anivibe

Нативное приложение iOS 17+ на SwiftUI и AVPlayer. Доработка существующего проекта от 13.10.2026: исправления плеера и серий, русские метаданные, библиотека, локальное оформление и усиление синхронизации.

**Это промежуточная реализация ТЗ, а не готовая социальная платформа.** Друзья, совместный просмотр, очки дружбы, магазин, комментарии, росписи, модерация и push-уведомления ещё не реализованы. Папки и оформление пока не синхронизируются между устройствами.

## Проверенный статус

- `AnivibeCore`: **128 тестов, 0 ошибок, 0 пропусков** в финальном запуске с `ANIVIBE_LIVE_TESTS=1`.
- Включены живые проверки AniList, Shikimori, AniLiberty/Anilibria и легальных тестовых HLS-потоков.
- PostgreSQL 15: миграции, сохранение старых строк, RLS, разграничение нумерации, удаление истории и 8 конкурентных обновлений проверены на локальной базе.
- SwiftUI-файлы прошли `swiftc -frontend -parse`. **Это не проверка типов, не сборка iOS и не запуск на устройстве.** macOS/Xcode в рабочей среде отсутствовали.
- Реальная отправка email, Google OAuth, Keychain, жесты, PhotosPicker, AVPlayer и PiP на iPhone не проверены.

Подробности: [отчёт](docs/IMPLEMENTATION_REPORT.md), [аудит](docs/AUDIT.md), [проверки](docs/QA.md), [настройка и VPS](docs/SETUP.md), [исходное ТЗ](docs/TECHNICAL_REQUIREMENTS.md).

## Что изменено

### Эпизоды и просмотр

Нумерация AniList и конкретного видеоматериала не считается автоматически одной и той же. Кнопка «Выбрать серию» открывает отдельный список:

- каталог AniList — его известные эпизоды;
- Kodik — фактические серии выбранного материала/озвучки с оригинальным сезоном и номером.

Сезоны 0, разрывы нумерации и одинаковые названия не теряются. У источников с разной нумерацией сохраняется отдельный прогресс по стабильному идентификатору материала/перевода/сезона/серии. Не применяется выдуманный сдвиг нумерации.

В Steel Ball Run проверенный ответ AniList содержит 3 вышедшие серии текущей части, а у ряда озвучек Kodik есть 4 элемента сезона 6. В приложении доступны оба представления. Это не утверждение, что четвёртый элемент Kodik соответствует четвёртой серии AniList.

### Плеер

Качество, скорость, аудио и субтитры вынесены в управляемую модальную панель. Скрытие контролов блокируется при открытых панелях, перемотке, подготовке и буферизации; после окончания взаимодействия начинается новый таймер. Переключение качества сохраняет позицию и состояние паузы, а старые асинхронные обработчики не могут применить настройки к новому AVPlayerItem.

В «Смотрю» и историю сохраняется только фактический просмотр основного плеера, а не открытие карточки/плеера или тестовый поток. Альтернативный KodikPlayerScreen сохранён; его история и прогресс пока не подключены к общему хранилищу.

### Каталог и библиотека

- Русские названия/описания из Shikimori с сохранением оригинала и указанием источника.
- Поиск через AniList и Shikimori с сопоставлением строго по MAL ID, а не похожему названию.
- Нормализация, альтернативные названия, транслитерация запроса и ограниченный поиск по опечаткам в кэшированном индексе.
- Контекстное меню карточек → выбор нескольких папок с актуальными отметками, без дублей.
- История отделена от «Смотрю»; удаление синхронизируется через tombstone-записи, а не исчезает лишь на одном устройстве.
- Персональные библиотеки разных аккаунтов и гостя хранятся в разных файлах. Гостевые данные не загружаются в чужой аккаунт автоматически.

### Оформление

- Перетаскивание папок и тайтлов с сохранением порядка на устройстве.
- Более сдержанные карточки папок.
- Цветовые пресеты, ColorPicker, централизованный акцент, контраст текста заполненных кнопок и сброс к фиолетовому.
- Системный выбор пользовательского фона, предпросмотр, верх/центр/низ, подложка для текста, уменьшенная JPEG-копия до 2048 пикселей.
- Закрепление библиотеки на главной через долгое нажатие на заголовок библиотеки или переключатель в настройках. Это **не системный виджет iOS**.

### Авторизация и сервер

Сохраняется Supabase: Auth/GoTrue выдаёт и проверяет сессии, PostgREST обслуживает библиотеку, PostgreSQL/RLS разграничивает доступ. Добавлены клиентские вызовы подтверждения регистрации кодом, повторной отправки и Google OAuth через системный ASWebAuthenticationSession + PKCE S256. SMTP и Google client secret остаются только на сервере.

Это не означает, что вся серверная часть ТЗ завершена: отсутствуют социальная схема/API и полноценные профили, а отдельный фиксированный лимит попыток **для каждого кода** ещё не реализован. Используются ограничения GoTrue на отправку, срок действия и проверочные запросы.

## Быстрый старт

На Mac с Xcode 16+:

```bash
cp Config/Secrets.example.xcconfig Config/Secrets.xcconfig
open Anivibe.xcodeproj
```

Заполните собственный Bundle Identifier и команду подписи. Выберите iPhone/Simulator и запустите сборку. Если нужен собственный Xcode-проект, сохранён `project.yml` и генератор `scripts/generate_xcodeproj.py`.

Без Supabase приложение работает в локальном режиме. Без собственного `ANIVIBE_KODIK_TOKEN` Kodik выключен: общий токен из исходного архива удалён. Используйте только источники, на которые у вас есть необходимые права.

В `.xcconfig` URL записываются как `https:/$()/host`, иначе `//` начинает комментарий. Service-role ключи, пароли БД, SMTP и Google client secret в клиент не помещать.

## Тесты

```bash
cd Packages/AnivibeCore
swift test
ANIVIBE_LIVE_TESTS=1 swift test
```

Обычный запуск пропускает 6 внешних интеграционных тестов. Финальный живой запуск выполнил все 128 тестов.

```bash
# Только выделенная тестовая PostgreSQL, не production!
PGURL=postgresql://postgres@127.0.0.1:5432/postgres bash supabase/tests/rls_test.sh
```

SQL-скрипт создаёт и удаляет базу `anivibe_rls_test`. Для него нужен административный пользователь PostgreSQL. Тестовые роли создаются только если отсутствуют.

## Миграции — важно

Новая версия клиента требует все три миграции в порядке имён. Две новые миграции меняют ключ конфликта прогресса и синхронизацию истории. **Старые клиенты после этого не совместимы со старым `on_conflict`**: обновите все устройства согласованно. Сначала резервная копия и staging, затем сервер, затем новый клиент.

В существующем проекте Supabase:

```bash
supabase link --project-ref YOUR_PROJECT_REF
supabase db push
```

Для проекта, где первая миграция ранее применялась вручную, сначала сверяйте историю миграций; не запускайте её повторно вслепую. Подробно — в [SETUP](docs/SETUP.md).

## Структура

- `Anivibe/App`, `Core`: композиция, наблюдаемые хранилища, Keychain, OAuth.
- `Anivibe/Features`: SwiftUI-экраны и AVPlayer.
- `Packages/AnivibeCore`: модели, каталог, провайдеры, библиотека, HTTP, Supabase.
- `supabase/migrations`, `tests`, `templates`: реальная схема, политики и шаблон письма.
- `docs`: аудит, отчёт, настройки, проверки и наблюдённые обезличенные метаданные эпизодов.

Сохраняемые старые `library.json` и `collections.json` не требуют удаления. Опциональные поля декодируются со старым форматом. Повреждённый файл не заменяется пустой библиотекой при следующем сохранении.
