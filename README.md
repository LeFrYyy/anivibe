# Anivibe

Нативное iOS-приложение для каталога и просмотра аниме (SwiftUI + AVPlayer). Вдохновлено пользовательским сценарием Anixart, но дизайн, код и иконка — собственные.

> **Честный статус.** Проект собран в Linux-окружении **без Xcode и без macOS**. Бизнес-логика (пакет `AnivibeCore`) скомпилирована и покрыта тестами (`swift test`: 90 тестов, 0 ошибок), Supabase-миграция и RLS проверены на реальном PostgreSQL 15. **iOS-приложение (SwiftUI-слой, AVPlayer, PiP, Keychain, WebView-плеер) не собиралось и не запускалось** ни в симуляторе, ни на iPhone — файлы прошли только синтаксическую проверку `swiftc -parse`. Клиент Kodik написан по публичной документации API и **не проверен с реальным токеном** (его у автора нет). При первой сборке в Xcode возможны мелкие ошибки компиляции, которые нужно поправить. Подробно — в разделе [13.12 Итоговый статус](#1312-итоговый-статус).

## 13.4 Каталог: AniList

* Эндпоинт: `https://graphql.anilist.co`, без ключа. Лимит — 90 запросов/мин (сейчас временно понижен до **30/мин**); клиент ограничивает частоту сам и повторяет запрос после 429.
* Ключ не нужен; OAuth AniList не используется.
* **Условия использования AniList ([anilist.co/terms](https://anilist.co/terms)) — прочитайте до публикации.** Некоммерческое использование бесплатно; коммерческое — бесплатно при доходе до $150/мес; запрещено массовое накопление (hoarding) данных. **Пункт 5 запрещает использовать API для создания сервиса-конкурента спискам/трекеру AniList.** Встроенная библиотека Anivibe («Смотрю», «Просмотрено» и т.д.) может трактоваться как такой сервис. Для личного использования риск минимален; перед публикацией в App Store свяжитесь с AniList или замените источник каталога (реализуйте протокол `CatalogService`: Kitsu, Shikimori, Jikan/MyAnimeList — у каждого свои условия).

### Онлайн-озвучки через Kodik (WebView)

Если задан `ANIVIBE_KODIK_TOKEN`, на странице аниме появляется раздел **«Смотреть с русской озвучкой»**:

1. Кнопка «Найти озвучки» запрашивает `kodik-api.com/search` по всем известным названиям тайтла (русское, ромадзи, английское, синонимы) с параметрами `with_episodes=true`, `with_episodes_data=true`, `limit=100`.
2. Результаты группируются по материалу Kodik (один тайтл приходит несколько раз — по разу на каждую озвучку); лучший материал выбирается нечётким сравнением названий (`TitleMatcher`, учитывает номер сезона в названии), при равенстве — по году. Если название отличается от каталожного, интерфейс честно показывает «Найдено у Kodik: …».
3. Пользователь выбирает озвучку (AniDUB, Anilibria, SHIZA Project и т.д. — сколько вернул Kodik, столько и вариантов; субтитры помечены отдельно) и серию; воспроизведение открывается во встроенном **WKWebView-плеере Kodik**.

**Ограничения (важно):**
* Kodik отдаёт только HTML-плеер (iframe). Прямые HLS-ссылки из него **намеренно не извлекаются** — это запрещено условиями Kodik. Поэтому в этом режиме недоступны: сохранение/восстановление позиции, автопереход к следующей серии, PiP, жесты и выбор дорожек средствами Anivibe — всё это остаётся в родном AVPlayer-плеере для HLS-источников.
* Выбор серии/озвучки/качества и возможная реклама — внутри веб-плеера Kodik.
* Клиент написан по публичной документации Kodik API и **не проверен с реальным токеном**: модульные тесты проверяют разбор документированного формата ответа на фикстурах, но живой ответ может отличаться.
* Токен получается при регистрации на kodik.biz (партнёрская программа для владельцев сайтов/приложений). Право показывать контент студий озвучки и условия Kodik — зона ответственности владельца токена.

Код: `Packages/AnivibeCore/Sources/AnivibeCore/Online/` (клиент и модели, покрыты тестами) и `Anivibe/Features/Online/` (раздел на странице аниме + веб-плеер).

### Как выбирается источник в плеере

**Как сопоставляются тайтлы.** AniList отдаёт `idMal` (ID MyAnimeList = ID Shikimori). Anilibria возвращает `mal.id` у каждого релиза, Kodik ищет по `shikimori_id` — поэтому сначала ищем точное совпадение по ID. Если ID нет, сравниваем названия с учётом сезона, но кандидаты с *другим* ID отбрасываются. Подмены вроде «первый тайтл того же года» убраны: так «Black Clover 2nd Season» раньше превращался в «Чёрный факел». Если у источника тайтла нет, приложение честно пишет «не найдено». У Anilibria три зеркала API (`anilibria.top`, `api.anilibria.app`, `aniliberty.top`): при сетевой ошибке или 5xx (Cloudflare 520) провайдер переключается на следующее и запоминает рабочее.

1. При открытии серии `ProviderRegistry` опрашивает включённые провайдеры по порядку: сначала `manifest` (если задан `ANIVIBE_MANIFEST_URL`), затем `anilibria`, затем `test-streams`. Anilibria отключается в «Настройки → Источники видео → Anilibria».
2. Каждый провайдер сопоставляет тайтл: сначала по `anilistId`, затем по названиям (`TitleMatcher`, учитывает ромадзи/английское/родное название и синонимы), а серию — по номеру (`EpisodeNumberParser`).
3. Пользователь может сменить источник в плеере (кнопка «Источники») и отключить тестовые потоки в «Настройки → Источники видео → Тестовые потоки».

### Свой манифест

Скопируйте `docs/stream-manifest.example.json`, укажите HTTPS-ссылки на свои `.m3u8`/`.mp4`, опубликуйте файл и пропишите `ANIVIBE_MANIFEST_URL`. Формат и требования (HTTPS, CORS не нужен, субтитры внутри HLS) — в `docs/stream-manifest.md`.

## 13.6 Бэкенд: Supabase

### Облачный проект

1. Создайте проект на [supabase.com](https://supabase.com) → Project Settings → API: скопируйте **Project URL** и **anon / publishable key**.
2. Примените миграцию:
   ```bash
   cp .env.example .env    # заполните SUPABASE_PROJECT_REF, SUPABASE_DB_PASSWORD
   supabase login
   supabase link --project-ref <ref>
   supabase db push        # применит supabase/migrations/20261011000000_anivibe_init.sql
   ```
   Альтернатива: вставьте содержимое миграции в SQL Editor панели Supabase и выполните.
3. Authentication → Providers → Email: включено. Для быстрой проверки можно отключить «Confirm email»; при включённом подтверждении пользователь должен перейти по ссылке из письма до входа.
4. Пропишите URL и anon-ключ в `Config/Secrets.xcconfig` и пересоберите приложение.

### Локально

```bash
supabase start           # нужен Docker; применит миграции
supabase status          # API URL (http://127.0.0.1:54321) и anon key
```
Для симулятора укажите `ANIVIBE_SUPABASE_URL = http:/$()/127.0.0.1:54321` (в `Info.plist` разрешён только `NSAllowsLocalNetworking`). Для iPhone используйте IP Mac в локальной сети.

### Схема и безопасность

| Таблица | Содержимое | Ключ уникальности |
|---|---|---|
| `library_entries` | статус списка, избранное, название, обложка | `(user_id, anime_id)` |
| `watch_progress` | позиция и длительность по серии | `(user_id, anime_id, episode)` |
| `watch_history` | история просмотров | `id` (uuid, генерирует клиент) |

* RLS включён на всех таблицах: пользователь видит и меняет только строки с `user_id = auth.uid()`; `user_id` подставляется по умолчанию; роли `anon` доступ закрыт.
* CHECK-ограничения: допустимые статусы, только `https`-обложки, номер серии 1…10000, разумные пределы позиции; триггер не даёт клиенту записать время `updated_at`/`watched_at` из будущего (важно для слияния «последняя запись побеждает»).
* В приложении используется только публичный ключ; токены хранятся в Keychain (`KeychainTokenStore`).

### Какие API вызывает приложение

| Запрос | Назначение |
|---|---|
| `POST /auth/v1/signup` | регистрация |
| `POST /auth/v1/token?grant_type=password` | вход |
| `POST /auth/v1/token?grant_type=refresh_token` | обновление сессии |
| `POST /auth/v1/recover` | сброс пароля |
| `POST /auth/v1/logout` | выход |
| `GET/POST /rest/v1/<таблица>?on_conflict=...` | загрузка и upsert библиотеки, прогресса, истории |

### Проверка RLS

```bash
# на любом PostgreSQL 15+ (создаёт и удаляет базу anivibe_rls_test; не запускайте на продакшене)
PGURL=postgresql://postgres@localhost:5432/postgres ./supabase/tests/rls_test.sh
```
Скрипт подменяет схему `auth` заглушкой (`local_auth_stub.sql`), применяет миграцию и выполняет 13 проверок (`rls_check.sql` — ручной вариант для SQL Editor). В этом окружении все 13 проверок прошли на PostgreSQL 15.

### Без своего Mac: сборка в GitHub Actions + установка через Sideloadly/AltStore

В репозитории есть workflow `.github/workflows/ios.yml`: облачный Mac-раннер GitHub прогоняет тесты `AnivibeCore` и собирает **неподписанный** `.ipa` для реального iPhone (arm64). Сборка для симулятора на устройство не встанет — нужна именно device-сборка, workflow делает её.

1. Создайте репозиторий на GitHub и запушьте проект (`git init && git add -A && git commit -m init && git remote add origin … && git push -u origin main`).
2. Вкладка **Actions** → workflow «iOS» → **Run workflow**. Для публичных репозиториев macOS-раннеры бесплатны; в приватных минуты macOS идут с множителем ×10.
3. Когда job «Unsigned iPhone .ipa» станет зелёным, скачайте артефакт **Anivibe-unsigned-ipa** (внутри `Anivibe.ipa`).
4. Установите на iPhone через **Sideloadly** или **AltStore/SideStore** (Windows подходит): они подпишут `.ipa` вашим бесплатным Apple ID. Понадобятся обычные iTunes/iCloud с сайта Apple (не из Microsoft Store), пароль приложения при двухфакторке и включённый Режим разработчика на iPhone.
5. Бесплатная подпись живёт **7 дней** — затем переподписать (SideStore/Sideloadly умеют автообновление по Wi-Fi, если компьютер иногда включён). Постоянная установка без переподписи — только TrollStore на старых iOS (Anivibe требует iOS 17+, поэтому подходит лишь ровно iOS 17.0).

**Ключи в CI (необязательно).** Чтобы сборка с GitHub включала Supabase/Kodik/манифест, добавьте их как секреты репозитория: **Settings → Secrets and variables → Actions → New repository secret** с именами `ANIVIBE_SUPABASE_URL`, `ANIVIBE_SUPABASE_ANON_KEY`, `ANIVIBE_KODIK_TOKEN`, `ANIVIBE_MANIFEST_URL`. Шаг «Write Secrets.xcconfig» запишет их в конфиг при сборке; без секретов собирается локальный режим. Зашитые в `.ipa` ключи видны всем, кто скачает артефакт, — Kodik-токен и anon-ключ Supabase являются клиентскими, но с ними лучше держать репозиторий приватным.

**Статус workflow:** проверен на практике — `macos-15`, сборка и тесты проходят (оба job зелёные). Если при ваших изменениях сборка упадёт, лог шага «Build unsigned device app» прикладывается артефактом `xcodebuild-log`.

## 13.9 Устранение неполадок

| Симптом | Причина и решение |
|---|---|
| Ошибки компиляции SwiftUI при первой сборке | Слой приложения не компилировался (не было Xcode). Исправьте по подсказкам Xcode — обычно это мелочи типа недостающего `import`, аннотаций `@MainActor` или несовпадения сигнатур. Логику в `AnivibeCore` трогать, как правило, не нужно — она собрана и протестирована |
| «Cannot open project» / ошибка формата | Нужен Xcode 16+. Либо `xcodegen generate` (по `project.yml`) |
| Ошибки подписи: «No account for team», «Failed to register bundle identifier» | Укажите свой Team и уникальный Bundle ID (13.7) |
| «Untrusted Developer» на iPhone | Доверьте сертификату в Настройки → Основные → VPN и управление устройством |
| Приложение перестало запускаться через неделю | Срок профиля бесплатного Apple ID — 7 дней, переустановите из Xcode |
| AniList: 429 Too Many Requests | Превышен лимит (30/мин). Клиент ждёт `Retry-After` и повторяет; подождите минуту |
| AniList: 400/404 | Изменилась схема GraphQL или неверный ID тайтла — проверьте запрос в `AniListQueries.swift` на [anilist.co/graphiql](https://anilist.co/graphiql) |
| AniList: 403 | Блокировка по IP/региону или нарушение ToU — проверьте с другой сети |
| Supabase: 401 | Неверный anon-ключ или истёкшая сессия (приложение обновляет токен само; иначе выйдите и войдите снова) |
| Supabase: 403 / `new row violates row-level security policy` | Миграция не применена или запрос без сессии пользователя; проверьте `rls_test.sh` |
| Supabase: 404 на `/rest/v1/...` | Таблицы не созданы — выполните `supabase db push` |
| «Email not confirmed» | Подтвердите почту или отключите подтверждение в Authentication → Providers → Email |
| «Не удалось найти сервер» / DNS | Нет сети или неверный `ANIVIBE_SUPABASE_URL` (проверьте `https:/$()/` в xcconfig) |
| Видео не запускается, «Источник недоступен» | Потоки нет у провайдера или он отключён; проверьте URL `.m3u8` в Safari на iPhone |
| Ошибка ATS (`NSURLErrorAppTransportSecurityRequiresSecureConnection`) | Используйте HTTPS. Произвольный HTTP намеренно не разрешён |
| Нет выбора аудио/субтитров | В потоке нет альтернативных дорожек — проверьте на Apple bipbop |
| Раздел «Смотреть с русской озвучкой» не появляется | Не задан `ANIVIBE_KODIK_TOKEN` в `Config/Secrets.xcconfig` (и нужен перезапуск сборки) |
| «Требуется авторизация (401)» в разделе озвучек | Токен Kodik неверный или отозван — проверьте на kodik.biz |
| «Kodik не нашёл этот тайтл» | У Kodik нет тайтла ни под одним из названий AniList, либо живой формат ответа отличается от документированного (клиент не проверен с реальным токеном) |
| Веб-плеер Kodik чёрный/не грузится | Нет сети, Kodik недоступен или ссылка устарела; закройте и откройте серию заново. Наш AVPlayer-плеер при этом работает независимо |
| Прогресс не сохраняется/не восстанавливается | Позиция пишется периодически и при паузе/уходе в фон; досмотренная серия (≥ 90 %) считается завершённой, и предлагается следующая — это намеренно |
| Данные не синхронизируются | Проверьте вход в «Профиль», сеть и что миграция применена; локальные изменения сливаются с облачными по `updated_at` |

## 13.10 Как добавить провайдера видео

1. Создайте тип в `Packages/AnivibeCore/Sources/AnivibeCore/Providers/`, реализующий протокол `VideoSourceProvider`:
   ```swift
   public struct MyProvider: VideoSourceProvider {
       public static let providerID: ProviderID = "my-provider"
       public let id: ProviderID = MyProvider.providerID
       public let displayName = "Мой источник"
       public let capabilities: ProviderCapabilities = [.search, .episodeList]

       public func search(title: String) async throws -> [ProviderTitle] { /* ... */ }
       public func episodes(for title: ProviderTitle) async throws -> [ProviderEpisode] { /* ... */ }
       public func resolve(_ episode: ProviderEpisode) async throws -> PlaybackSource { /* ... */ }
       public func checkAvailability(_ episode: ProviderEpisode) async -> Availability { /* ... */ }
       // match(anime:) уже реализован по умолчанию (anilistId → название)
   }
   ```
2. Ошибки сообщайте через `VideoSourceError` — у них есть понятные пользователю тексты.
3. Зарегистрируйте провайдера в `Anivibe/App/AppEnvironment.swift` (массив `providers`, порядок = приоритет).
4. Добавьте тесты по образцу `ProviderTests.swift` (подменный `HTTPTransport` из `TestSupport.swift`).
5. **Подключайте только источники, на контент которых у вас есть права**, и не обходите DRM.
